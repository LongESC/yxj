## 1. 总体设计

### 1.1 数据库选型

| 组件 | 用途 | 说明 |
|---|---|---|
| PostgreSQL 15+ | 业务数据 | 用户、知识库、文档、会话、消息、反馈、审计 |
| Milvus | 向量检索 | 切片向量存储与混合检索（稠密 + BM25） |
| Redis | 缓存/队列 | Embedding 缓存、会话上下文、限流计数 |
| MinIO | 对象存储 | 原始文件存储 |

### 1.2 设计原则

- 时间统一 `TIMESTAMPTZ` 存 UTC，展示层转本地时区
- 自增主键统一 `BIGSERIAL`
- 结构化配置字段用 `JSONB`（支持 GIN 索引）
- 数组字段用原生数组（`BIGINT[]`、`TEXT[]`）
- 逻辑删除用 `status` 字段，禁止物理删除业务数据
- 所有表必须有 `created_at`；可变表加 `updated_at`

### 1.3 模块前缀

| 前缀 | 模块 |
|---|---|
| `sys_` | 系统（用户、角色、审计） |
| `kb_` | 知识库（知识库、文档、切片） |
| `chat_` | 对话（会话、消息、引用、反馈） |
| `prompt_` | 提示词模板 |
| `model_` | 模型配置 |

## 6. Milvus 集合设计

### 6.1 Collection：`kb_chunks`

```python
from pymilvus import MilvusClient, DataType, Function, FunctionType

client = MilvusClient(uri=settings.MILVUS_URI)
schema = client.create_schema(auto_id=False, enable_dynamic_field=False)

# 主键与外键
schema.add_field("chunk_id", DataType.INT64, is_primary=True)   # 对应 kb_chunk.id
schema.add_field("kb_id", DataType.INT64, is_partition_key=True) # 多租户隔离
schema.add_field("doc_id", DataType.INT64)
schema.add_field("version_id", DataType.INT64)
schema.add_field("status", DataType.INT8)

# 元数据
schema.add_field("content", DataType.VARCHAR, max_length=8192,
                 enable_analyzer=True, analyzer_params={"type": "chinese"})
schema.add_field("title_path", DataType.VARCHAR, max_length=1024)
schema.add_field("page_no", DataType.INT32)

# 向量
schema.add_field("dense_vec", DataType.FLOAT_VECTOR, dim=1024)   # text-embedding-v3
schema.add_field("sparse_vec", DataType.SPARSE_FLOAT_VECTOR)

# BM25 Function（Milvus ≥ 2.5）
schema.add_function(Function(
    name="bm25_fn",
    function_type=FunctionType.BM25,
    input_field_names=["content"],
    output_field_names=["sparse_vec"],
))

# 索引
index_params = client.prepare_index_params()
index_params.add_index("dense_vec", index_type="HNSW",
                       metric_type="COSINE",
                       params={"M": 16, "efConstruction": 200})
index_params.add_index("sparse_vec", index_type="SPARSE_INVERTED_INDEX",
                       metric_type="IP", params={"drop_ratio_build": 0.2})

client.create_collection("kb_chunks", schema=schema, index_params=index_params)
client.load_collection("kb_chunks")
```

### 6.2 混合检索

```python
from pymilvus import AnnSearchRequest, RRFRanker

async def hybrid_search(query: str, kb_ids: list[int], top_k: int = 50) -> list[Chunk]:
    dense = await embed_one(query)  # DashScope
    expr = f"kb_id in {list(kb_ids)} and status == 1"

    reqs = [
        AnnSearchRequest([dense], "dense_vec",
                        {"metric_type": "COSINE", "params": {"ef": 128}},
                        limit=top_k, expr=expr),
        AnnSearchRequest([query], "sparse_vec",
                        {"metric_type": "IP"},
                        limit=top_k, expr=expr),
    ]

    res = client.hybrid_search(
        collection_name="kb_chunks",
        reqs=reqs, ranker=RRFRanker(k=60), limit=top_k,
        output_fields=["doc_id", "version_id", "title_path", "page_no", "content"],
    )
    return [to_chunk(h) for h in res[0]]
```

### 6.3 关键约定

| 约定 | 说明 |
|---|---|
| 权限过滤前置 | `kb_id` 写在 `expr` 中，检索阶段生效 |
| Partition Key | `kb_id` 为分区键，知识库级操作走 partition |
| 蓝绿切换 | 集合结构变更时新建 `kb_chunks_v{n}` → 建索引 → 切流 → 删旧 |
| 数据对齐 | `chunk_id` 与 PostgreSQL `kb_chunk.id` 严格一致 |

## 7. 数据一致性

PostgreSQL 与 Milvus 无跨库事务，采用**最终一致 + 补偿**：

```
1. 先写 PostgreSQL（切片记录，status=0 未生效）
2. 再写 Milvus（批量 upsert）
3. Milvus 成功后回调更新 PostgreSQL status=1
4. 失败则任务重试（最多 3 次），仍失败标记 status=2 并告警
5. 对账任务每日扫描修复不一致
```

## 8. 索引与性能

### 8.1 PostgreSQL 索引策略

| 表 | 索引 | 类型 | 用途 |
|---|---|---|---|
| `kb_document` | `(kb_id, status)` | B-tree | 按知识库查文档状态 |
| `kb_document` | `(updated_at)` | B-tree | 按时间排序 |
| `kb_chunk` | `(document_id, version_id)` | B-tree | 按文档版本查切片 |
| `kb_chunk` | `(kb_id, status)` | B-tree | 按知识库查有效切片 |
| `chat_message` | `(conversation_id, id)` | B-tree | 按会话查消息 |
| `chat_message` | `(created_at)` | B-tree | 按时间范围查询 |
| `chat_feedback` | `(handled, created_at)` | B-tree | 未处理反馈列表 |
| `sys_audit_log` | `(action, created_at)` | B-tree | 按操作类型查审计 |
| `sys_audit_log` | `(user_id, created_at)` | B-tree | 按用户查审计 |
| `kb_faq` | `keywords` | GIN | FAQ 关键词搜索 |

### 8.2 分区策略（可选）

大表按月分区候选：
- `chat_message`：按 `created_at` 月分区
- `sys_audit_log`：按 `created_at` 月分区

一期可不分区，但 DDL 预留分区键。

## 9. 缓存设计（Redis）

| 对象 | Key | TTL | 失效条件 |
|---|---|---|---|
| Embedding | `emb:{text_sha256}` | 30d | 模型版本变更 |
| 检索结果 | `qa:ret:{kb_set}:{q_hash}` | 30min | 索引版本变更 |
| 高频答案 | `qa:ans:{kb_set}:{q_hash}` | 2h | 同上 |
| 用户权限 | `perm:{user_id}` | 10min | 角色变更 |
| 会话上下文 | `conv:{id}:ctx` | 1h | 新消息写入 |
| 模型配额计数 | `quota:{endpoint}:{minute}` | 60s | — |
| LangGraph checkpoint | `lg:ckpt:{thread_id}` | 24h | 会话结束 |

## 12. 迁移管理

- 工具：Alembic
- 迁移脚本命名：`xxxx_<动作>_<对象>.py`
- 每个迁移必须实现 `upgrade` 与 `downgrade`
- 加索引用 `CREATE INDEX CONCURRENTLY`（避免锁表）
- Milvus 集合变更走蓝绿切换，不走迁移

常用命令：

```bash
alembic revision --autogenerate -m "init_tables"
alembic upgrade head
alembic downgrade -1
alembic current
alembic history
```
